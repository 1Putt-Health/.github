# Contributing

Thanks for your interest in 1Putt Health. This is our organization-wide default guide; a repository may override it with its own `CONTRIBUTING.md`.

Most of our work lives in private client repositories. If you're an external contributor to one of our public projects, welcome — here's how we like to work.

## Ground rules

- **Open an issue first** for anything non-trivial, so we can align before you build.
- **Keep changes focused.** One concern per pull request; smaller diffs get reviewed faster.
- **Never commit secrets** — no credentials, tokens, `.env` files, or client data. See [SECURITY.md](./SECURITY.md).
- **No PHI, ever.** Do not include protected health information in code, tests, fixtures, screenshots, or issues.

## Pull requests

1. Fork or branch, and make your change.
2. Make sure the build passes and any tests are green.
3. Write a clear PR description: what changed and why. Link the issue it closes.
4. A maintainer will review. We may ask for changes — that's normal.

## Reporting bugs &amp; requesting features

Use the issue templates. Good reports include what you expected, what happened, and how to reproduce it.
